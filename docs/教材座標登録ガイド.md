# 教材座標登録ガイド

TeachArm では、カメラ映像上の教材領域（質問文・文章行）を JSON ファイルで定義します。このガイドでは、実際の教材を撮影して座標を測定・登録する手順を説明します。

---

## 1. 座標系の理解

### 1.1 正規化座標 (0.0 ~ 1.0)

TeachArm は**正規化座標**を使用します。これにより、カメラ解像度に依存しない柔軟な設定が可能です。

```
(0.0, 0.0) ────────────────── (1.0, 0.0)
    │                              │
    │      カメラ映像               │
    │                              │
(0.0, 1.0) ────────────────── (1.0, 1.0)
```

- **x**: 左端 0.0 → 右端 1.0
- **y**: 上端 0.0 → 下端 1.0
- **w (width)**: 幅（0.0 ~ 1.0）
- **h (height)**: 高さ（0.0 ~ 1.0）

### 1.2 バウンディングボックス (bbox)

各領域は矩形で定義します：

```json
{
  "bbox": {
    "x": 0.1,    // 左上のx座標（左端からの割合）
    "y": 0.2,    // 左上のy座標（上端からの割合）
    "w": 0.6,    // 幅（画面幅に対する割合）
    "h": 0.15    // 高さ（画面高さに対する割合）
  }
}
```

## 2. 座標測定の手順

### ステップ1: カメラ映像のキャプチャ

1. TeachArm サーバーを起動：
   ```bash
   python -m teacharm.main
   ```

2. Control Panel にアクセス：
   ```
   http://<raspberry-pi-ip>:3000
   ```

3. カメラ映像を確認し、スクリーンショットを保存

### ステップ2: 画像編集ツールで座標測定

推奨ツール: GIMP / Photoshop / Preview.app（macOS）

1. スクリーンショットを開く
2. 画像サイズを確認（例: 1920x1080）
3. 矩形選択ツールで領域を囲む
4. ピクセル座標を記録（例: x=192, y=108, w=1152, h=162）

### ステップ3: 正規化座標に変換

**変換式:**
```
正規化x = ピクセルx / 画像幅
正規化y = ピクセルy / 画像高さ
正規化w = ピクセル幅 / 画像幅
正規化h = ピクセル高さ / 画像高さ
```

**計算例（1920x1080の場合）:**
```
ピクセル座標: x=192, y=108, w=1152, h=162

正規化座標:
x = 192 / 1920  = 0.1
y = 108 / 1080  = 0.1
w = 1152 / 1920 = 0.6
h = 162 / 1080  = 0.15
```

### ステップ4: 座標変換ツール（オプション）

Python スクリプトで一括変換：

```python
# tools/convert_coordinates.py
def pixel_to_normalized(px, py, pw, ph, image_width, image_height):
    """ピクセル座標を正規化座標に変換"""
    return {
        "x": round(px / image_width, 3),
        "y": round(py / image_height, 3),
        "w": round(pw / image_width, 3),
        "h": round(ph / image_height, 3)
    }

# 使用例
result = pixel_to_normalized(
    px=192, py=108, pw=1152, ph=162,
    image_width=1920, image_height=1080
)
print(result)  # {'x': 0.1, 'y': 0.1, 'w': 0.6, 'h': 0.15}
```

## 3. 教材ファイルの編集

### 3.1 ファイル構造

教材は `materials/material_X.json` に保存：

```json
{
  "material_id": "A",
  "regions": [
    {
      "id": "q1",
      "type": "question",
      "bbox": { "x": 0.05, "y": 0.05, "w": 0.9, "h": 0.25 },
      "on_point": ["Q_INTRO"],
      "on_help": ["Q_HELP"]
    },
    {
      "id": "line1",
      "type": "line",
      "bbox": { "x": 0.1, "y": 0.35, "w": 0.8, "h": 0.08 },
      "on_point": ["READ_LINE"],
      "on_help": ["READ_HELP"]
    }
  ]
}
```

### 3.2 フィールド説明

| フィールド | 必須 | 説明 | 例 |
|----------|------|------|-----|
| `id` | ✅ | 領域の一意ID | `"q1"`, `"line1"` |
| `type` | ✅ | 領域タイプ | `"question"`, `"line"` |
| `bbox` | ✅ | バウンディングボックス | `{"x":0.1, "y":0.2, "w":0.6, "h":0.15}` |
| `on_point` | ✅ | ポイント時に実行するコマンド | `["Q_INTRO"]` |
| `on_help` | ⚠️ | ヒント時に実行するコマンド | `["Q_HELP"]` |

### 3.3 領域タイプ

- **`question`**: 質問文の領域
- **`line`**: 文章の1行
- **`diagram`**: 図表・イラスト（将来拡張用）

## 5. 座標精度のベストプラクティス

### 5.1 マージン設定

領域の境界に余裕を持たせる：

```json
// ❌ タイトすぎる（ポイントミスしやすい）
{ "x": 0.100, "y": 0.100, "w": 0.800, "h": 0.050 }

// ✅ 適度なマージン
{ "x": 0.05, "y": 0.08, "w": 0.9, "h": 0.08 }
```

### 5.2 重複領域の回避

領域が重ならないように配置：

```json
// ❌ 重複している
[
  { "id": "q1", "bbox": { "x": 0.1, "y": 0.1, "w": 0.8, "h": 0.3 } },
  { "id": "q2", "bbox": { "x": 0.1, "y": 0.2, "w": 0.8, "h": 0.3 } }
]

// ✅ 明確に分離
[
  { "id": "q1", "bbox": { "x": 0.1, "y": 0.1, "w": 0.8, "h": 0.25 } },
  { "id": "q2", "bbox": { "x": 0.1, "y": 0.4, "w": 0.8, "h": 0.25 } }
]
```

### 5.3 小数点精度

通常は小数点以下2桁で十分：

```json
// ✅ 読みやすく、十分な精度
{ "x": 0.05, "y": 0.10, "w": 0.90, "h": 0.20 }

// ❌ 過剰な精度（管理が煩雑）
{ "x": 0.052083, "y": 0.100000, "w": 0.899999, "h": 0.200001 }
```

## 7. トラブルシューティング

### Q1: 領域をポイントしても反応しない

**原因:**
- 座標が間違っている
- カメラ映像の解像度が変わった

**解決策:**
1. ログを確認: `grep "Point detected" logs/teacharm.log`
2. 正規化座標を再計算
3. マージンを広めに設定

### Q2: 複数の領域が同時に反応する

**原因:**
- 領域が重複している

**解決策:**
- `materials.py` の `contains()` ロジックを確認
- 各領域の bbox を見直し、重複を解消

### Q3: カメラ解像度を変更したらずれた

**原因:**
- 正規化座標は解像度に依存しないはずだが、カメラのアスペクト比が変わった

**解決策:**
- アスペクト比が変わった場合は座標を再測定
- 16:9 を維持することを推奨
