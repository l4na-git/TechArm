# TeachArm 開発環境セットアップ & 起動手順

このドキュメントでは、TeachArm の FastAPI ベース実行環境を構築し、ローカル（または Raspberry Pi）で起動するまでの流れをまとめる。

---

## 1. コンポーネント配置

| コンポーネント | 配置先 | 役割 |
|---|---|---|
| **ルールベースルーティング** | Raspberry Pi または開発 PC (ローカル処理) | ルーティング専用。次に実行すべきアクションをキーワードマッチで決定。ネットワーク断でも動作。 |
| **DeepSeek (Text Generation)** | 自宅サーバ (Tailscale経由) | 文章生成専用。1〜2文の短文生成、教材外拒否。必要時のみ呼び出し。 |
| **VOICEVOX Engine** | 自宅サーバ | `/audio_query` `/synthesis` で WAV 生成。Pi/PC 側の再生用に音声を渡す。 |
| **TeachArm FastAPI アプリ** | Raspberry Pi または開発 PC | Vision/Mapping/Dialog/Arm 制御を統合。Web カメラ入力と so-101 操作を担当。 |
| **Control Panel (React)** | Tailscale 内の任意 PC/Pi | カメラ映像・状態確認・手動操作。`CONTROL_PANEL_URL` でアクセス。Router/DeepSeek の統計情報表示。 |
| **TTS キャッシュ** | Pi/PC | `cache/tts/` に WAV を保存し、Pi から再生。 |

- サーバ側（自宅）で **DeepSeek と VOICEVOX Engine** を常駐させる。
- ルーティングは **ローカル（Pi/PC）でルールベース判定**し、ネットワーク断でも台本/拒否/復帰誘導が動作する。
- 展示会場の **Raspberry Pi**（または開発 PC）が TeachArm アプリを実行し、Tailscale でサーバへ接続する。
- Control Panel は同じ Pi でも別 PC でも良いが、Tailscale 内のみ公開とする。

---

## 2. 前提条件

### 自宅サーバ（DeepSeek/VOICEVOX）

- Linux サーバ（常時稼働推奨）
- Tailscale クライアント
- Ollama インストール済み（`ollama serve`）、DeepSeek モデル（例: deepseek-r1:7b）
- VOICEVOX Engine（Docker/バイナリ問わず）を `http://<tailscale-ip>:50021` で待受

### Raspberry Pi / 開発 PC 側

- Python 3.11（`pyproject.toml` に固定）
- [uv CLI](https://github.com/astral-sh/uv)（`curl -LsSf https://astral.sh/uv/install.sh | sh` などで導入）
- Node.js（Control Panel を開発する場合）
- Git / Tailscale クライアント
- Raspberry Pi では `libcamera` 対応の OS (64bit 推奨)、so-101 を USB で接続できること

---

## 3. リポジトリ初期化（Pi / 開発 PC）

```bash
git clone <this-repo>
cd TechArm
UV_PYTHON_PREFERENCE=managed uv venv --python 3.11
source .venv/bin/activate
uv pip install -r requirements.txt
```

---

## 4. 設定ファイル

### 3.1 環境変数 `.env`

テンプレートをコピーし、Tailscale IP やモデル名を実環境値で上書きする。

```bash
cp .env.example .env
# エディタで OLLAMA_BASE_URL / VOICEVOX_BASE_URL / CONTROL_PANEL_URL などを実値にする
```

主なキー：
- `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL`（自宅サーバー、Tailscale経由）
- `VOICEVOX_BASE_URL`, `VOICEVOX_SPEAKER_NAME`, `VOICEVOX_STYLE_NAME`
- `CONTROL_PANEL_URL`
- `OLLAMA_BASE_URL`, `OLLAMA_MODEL`（互換性のため残す）

### 3.2 コンフィグ類

- `config/voicevox_params.yaml`：話速や抑揚など音声パラメータ。デフォルト値あり、任意で調整。
- `config/arm_limits.json`：so-101 の安全領域と `safe_pose` を実測値で記入。
- `config/arm_calibration.json`：(u,v)→(x,y,z) 9点計測結果。`null` を計測値で更新。
- `materials/material_*.json`：教材 A/B の bbox（question/line）を記述。
- `scripts/common.yaml`：先生ロールやコマンド定義（初期値あり）。

Pi でカメラ/アームを接続する際は、`config/camera.yaml`（未作成であれば空ファイル）に解像度やホワイトバランス設定を記入する。

## 5. サービス起動DeepSeek / VOICEVOX）

1. 自宅サーバで Tailscale に接続する。
2. **Ollama (DeepSeek用)**：`ollama serve` を起動し、`curl http://127.0.0.1:11434/api/tags` でモデル一覧を確認。DeepSeek モデル（例: deepseek-r1:7b）をプル。
3. **VOICEVOX**：`voicevox_engine --host 0.0.0.0 --port 50021` などで起動し、`curl http://<tailscale-ip>:50021/speakers` で疎通確認。
4. `.env` の `DEEPSEEK_BASE_URL` / `VOICEVOX_BASE_URL` にサーバの Tailscale IP を設定する。

### 5.2 TeachArm FastAPI（Raspberry Pi / 開発 PC）

```bash
uv run -m teacharm.main 
```

依存更新時は `uv pip install -r requirements.txt`（または `uv pip sync requirements.txt`）を再実行する。requirements.txt には FastAPI / httpx などのバージョンを固定してあり、環境差異を最小化できる。

デフォルトで `http://0.0.0.0:8000` で待ち受ける。主なエンドポイント：

- `GET /health`
- `GET /api/materials`
- `POST /api/materials/select`
- `POST /api/events/pointer`
- `POST /api/dialogue`
- `POST /api/arm/move`
- `POST /api/arm/safe_pose`

Tailscale 内からアクセスする場合は、`http://<tailscale-ip>:8000` を API の公開先として使用する（スマホも Tailscale に参加させる）。

### 5.4 Control Panel（任意）

`control-panel/` ディレクトリに React + Vite 製の UI がある。Node.js をインストールし、以下で起動する。

```bash
cd control-panel
npm install
npm run dev -- --host 0.0.0.0 --port 5173
```

TeachArm API の URL は `VITE_TEACHARM_API_URL` で上書き可能。例：

```bash
VITE_TEACHARM_API_URL=http://100.xx.yy.zz:8000 npm run dev
```

Tailscale 内のスマホから確認する場合は以下を推奨：

- スマホを Tailscale に参加させる
- Control Panel の起動は `--host 0.0.0.0` を指定して外部端末からアクセス可能にする
- ブラウザで `http://<tailscale-ip>:5173` にアクセスする

`.env` の `CONTROL_PANEL_URL` には Tailscale 内で公開する URL（例：`http://teacharm-panel:5173`）を記入し、運用マニュアルでアクセス手順を共有する。

Control Panel では `scripts/common.yaml` の内容を読み書きできるため、展示会前には必ずバックアップを取得し、編集権限のある端末を限定して運用すること。

## 6. Raspberry Pi デプロイ

1. 事前に `.venv` を Pi 上で作成し、`pip install -r requirements.txt` を実行。
2. `sudo apt install python3-opencv libatlas-base-dev libatlas3-base`.
3. `systemd` ユニット例：

```ini
[Unit]
Description=TeachArm Control API
After=network.target

[Service]
WorkingDirectory=/home/pi/TechArm
Environment="PATH=/home/pi/TechArm/.venv/bin"
ExecStart=/home/pi/TechArm/.venv/bin/python -m teacharm.main
Restart=always

[Install]
WantedBy=multi-user.target
```

## 7. テスト・検証

- `python3 -m compileall teacharm` で静的チェック。
- `curl http://localhost:8000/health` で起動確認。
- `POST /api/events/pointer` に `{"u":0.1,"v":0.2,"event":"on_point"}` を送信し、教材マッピング→スクリプト→VOX 再生までを確認。

---

## 8. よくある調整ポイント

- VOICEVOX TTS が失敗する場合：`config/voicevox_params.yaml` を見直し、`VOICEVOX_BASE_URL` の Tailscale IP を確認。
- Ollama 応答遅延：`.env` の `OLLAMA_BASE_URL` が到達可能か `curl` で確認し、モデルを軽量化。
- 教材切り替え：`materials/*.json` を更新後、サーバを再起動（現状ホットリロード無し）。
