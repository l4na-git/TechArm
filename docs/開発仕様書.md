# TeachArm 開発仕様書

TeachArm は A4 一枚の教材を対象に、指差し認識・台本応答・ロボットアーム動作を組み合わせた展示会向けデモシステムである。本書は既存の展示会仕様書と技術スタック整理ドキュメントを踏まえ、実装を開始するための開発仕様を定義する。

---

## 1. スコープと前提

- 対象教材：国語文章題 A/B（`materials/japanese3article-1608-01.pdf` / `materials/japanese3article-1608-02.pdf` を A4 で印刷）。ページめくり無し。
- 入力：真上固定 Web カメラからの 720p 以上の静止画または 3–10fps のストリーム。
- 出力：ロボットアーム指差し、キャラクター TTS 音声（春日部つむぎ系）。
- 制御 PC：開発時 macOS/Windows/Linux、展示時 Raspberry Pi OS（64bit 推奨）。
- ネットワーク：展示会場はローカル閉域、LLM は Tailscale 越しに自宅サーバへ接続。
- 限定的な自由対話を許容。

---

## 2. アーキテクチャ方針

### 2.1 推奨構成

| レイヤ | 推奨技術 | 理由 |
|---|---|---|
| 共通言語 | Python 3.11 | OpenCV/YOLO/ロボット制御ライブラリを統合しやすい |
| Vision/Mapping API | FastAPI + WebSocket | カメラ処理と UI へ状態配信を同時に扱える |
| Control Panel | TypeScript + React + Vite | 迅速な UI 実装と状態可視化に適する |
| モデル管理 | Ultralytics YOLOv8n 手検出 or MediaPipe Hands | 軽量で Raspberry Pi でも動かしやすい |
| データ永続化 | JSON/SQLite | 教材データやログを簡易に保持 |
| メッセージング | asyncio Queue or Redis (任意) | Vision→Arm、Dialogue→TTS の非同期制御を単純に実装 |

### 2.2 プロセス分割

1. `vision-service`：カメラ取得、ArUco 検出、射影変換、手/指推定。
2. `mapping-service`：正規化座標 → 教材領域マッピング、デバウンス処理。
3. `dialogue-service`：台本応答、Ollama API 連携、意図分類。
4. `tts-player`：VOICEVOX エンジン呼び出しと WAV 再生。
5. `arm-controller`：座標キュー処理、フェイルセーフ。
6. `control-panel`：Web UI（状態表示・操作）。

開発効率を優先し、単一 FastAPI アプリ内で Vision/Mapping/Dialog/TTS/Arm のループを `asyncio` で統合し、UI 用に REST/WebSocket を提供する構成を推奨する。展示用 Raspberry Pi では `systemd` サービス化し自動起動させる。

## 3. モジュール別仕様

### 3.1 Vision サービス

- **入力**：`/dev/video0`（PC は OpenCV VideoCapture、Pi は `libcamera` 経由）、解像度 1280x720 固定。
- **キャリブレーション**：起動時および UI から再実行可。ArUco 4 マーカー（DICT_4X4_50）を検出し、透視変換を算出。
- **手検出モデル**：初期は色ベース＋輪郭（Step A）、安定化後に YOLOv8n (hand dataset) を使用（Step B）。モデルファイルは `models/hands/yolov8n-hand.pt` に配置。
- **指先推定**：
  1. 手領域の上端/指向きクラスタを抽出。
  2. 連続 5 フレームの移動平均。
  3. しきい値 40px 以上のジャンプは棄却。
- **出力**：正規化座標 (0–1) とステータスメタデータ（マーカー状態、手検出有無、エラーコード）。
- **ログ**：`logs/vision.log` に 1fps で JSON 出力。

### 3.2 教材データ・マッピング

- **フォーマット**：`materials/{material_id}.json`。先行ドキュメントのサンプル JSON を正式仕様とし、`regions[].bbox` は補正後画像基準。
- **優先度**：`type` ごとに `question > line > word`。複数ヒット時は面積最小。
- **デバウンス**：同一 region の再発火は 1.5 秒待機。UI から無効化可能。
- **近傍検索**：ヒットなし時は最近傍中心との距離が 0.05 未満なら補完。
- **教材切替**：UI から material_id を指定 → Vision に通知し、Mapping が JSON を再ロード。

### 3.3 Dialogue & TTS

- **処理フロー**：`region.script` > 汎用コマンド > Ollama（LLM）の順に判定。LLM は台本補助としてのみ利用し、自由対話は安全ガードを通過したものに限定する。
- **LLM 接続（Ollama 公式仕様に準拠）**：
  - プロトコル：HTTP/JSON。デフォルト待受 `http://127.0.0.1:11434`。
  - TeachArm 基準 URL：`http://<tailscale-ip>:11434`。
  - `GET /api/tags` で起動時にモデル一覧を確認し、 `.env` の `OLLAMA_MODEL` を検証。
  - `POST /api/chat` を使用。例：
    ```json
    {
      "model": "model-name",
      "messages": [
        {"role": "system", "content": "あなたは小学生の先生です。"},
        {"role": "user", "content": "こんにちは"}
      ],
      "stream": false
    }
    ```
  - 認証：Ollama 公式 API は認証無し。外部露出しない前提（Tailscale 内）。
  - タイムアウト：3 秒。失敗時は台本のフォールバックメッセージを返す。
- **台本管理**：`scripts/common.yaml` に先生ロール／汎用コマンド／ネガティブルールを定義し、region JSON の `script` が最優先。
- **安全ガード**：教材外質問はテンプレート「今は教材の話をしようね」で応答。ネガティブワードフィルタは YAML で段階的に追加可能。
- **TTS（VOICEVOX Engine 仕様に準拠）**：
  - Base URL：`http://<tailscale-ip>:50021`（自宅サーバ側）。
  - 合成手順：`GET /speakers` → `POST /audio_query`（`text`,`speaker`）→ `POST /synthesis`（`audio_query`）で WAV を取得。
  - 起動時に `GET /speakers` の結果から春日部つむぎの `speaker` ID を解決し、`.env` や設定ファイルに固定値を持たない設計とする。
  - 音声パラメータ（話速・抑揚など）は `config/voicevox_params.yaml` に記述し、運用時に調整できるようにする。
  - Pi 側ではオーディオ再生のみを行い、合成結果はサーバ側で `speaker+text+params` をハッシュ化したキーで `cache/tts/` に保存。
  - 再生：`pydub` または `simpleaudio` で逐次再生。音声再生中は新規応答をキューに積み、割り込みは行わない。

- **カメラ・アーム座標変換**：ArUco 補正後の正規化座標 `(u,v)` から教材面の 9 点（四隅・辺中点・中央）を計測し、(u,v)→(x,y,z) 変換テーブルを `config/arm_calibration.json` として保存。`z` は固定値とし、安全領域にクリップする。

### 3.4 ロボットアーム制御

- **対象機種**：so-101（USB 接続）。`/dev/ttyUSB*` または `/dev/ttyACM*` を `pyserial` で扱う。
- **制御方式**：座標指定（x,y,z,姿勢）。Vision の正規化座標をカリブ結果に基づく物理座標へ変換して使用。
- **コマンド I/F（TeachArm 設計）**：`connect(port,id)`、`ensure_calibrated()`、`move_xyz(x,y,z,speed)`、`go_safe_pose()`、`stop()` を最小 API とし、内部で LeRobot スタックを呼び出す。
- **キャリブレーション**：初回起動時に LeRobot のフルキャリブレーションを実施し、結果を保存。展示会ではコントロールパネルから原点補正などの簡易キャリブレーションを実行可能とする。
- **動作キュー**：`asyncio.Queue` に動作コマンドを入れ、1 件ずつ実行。タイムアウト時はフェイルセーフへ。
- **フェイルセーフ**：通信エラーで `E_ARM` を発火させ停止→ホーム復帰。UI からリセット命令を送れるよう REST エンドポイント`POST /arm/reset`を実装。
- **安全領域**：`config/arm_limits.json` で x,y,z の上下限を mm 単位で指定し、それ以外の指示は拒否。

### 3.5 コントロールパネル

- **表示**：カメラ映像（WebRTC もしくは Motion JPEG）、ArUco 検出状態、指先座標、選択 region、エラーコード、ログ抜粋。
- **操作**：教材選択、再キャリブレーション、デバウンス ON/OFF、アーム停止/ホーム復帰。
- **実装**：React + Tailwind CSS。状態は WebSocket (`/ws/state`) で購読。操作は REST (`/api/...`)。
- **ネットワーク**：Tailscale 内のホストのみで公開し、展示会場 LAN からはアクセス不可とする。念のため `.env` の BASIC 認証トークンを UI に埋め込み、二重で制限する。

## 4. 実行・デプロイ

1. **開発環境セットアップ**
   - `python -m venv .venv && source .venv/bin/activate`
   - `pip install fastapi uvicorn[standard] opencv-python numpy ultralytics pydantic pydub simpleaudio python-socketio`
   - `npm create vite@latest control-panel -- --template react-ts`（UI）
2. **設定ファイル**
   - `.env`（`.env.example` をコピーし、Ollama/Tailscale/VOICEVOX/CONTROL_PANEL_URL を実値で設定）
   - `config/camera.yaml`（解像度、露光）
   - `config/materials.json`（利用可能教材リスト）
   - `config/voicevox_params.yaml`（話速・抑揚などの初期パラメータ）
   - `config/arm_limits.json`（安全領域と安全姿勢）
   - `config/arm_calibration.json`（9 点計測による (u,v)→(x,y,z) 変換）
   - `scripts/common.yaml`（先生ロール／ネガティブルール／コマンド）
3. **Raspberry Pi**
   - `sudo apt install python3-opencv libatlas-base-dev`
   - YOLOv8n モデルを `models/` に配置
   - `systemd` ユニットを作成し、ブート時に `uvicorn main:app` を起動
4. **LLM/TTS サービス**
   - 自宅サーバで Ollama（LLM）と VOICEVOX Engine を常駐起動し、Tailscale 越しにアクセスする

---

## 5. 状態管理 & 監視

- 状態遷移：`IDLE -> MATERIAL_SELECTED -> CAPTURING -> CALIBRATING -> TRACKING -> TARGET_SELECTED -> RESPONDING -> IDLE`。エラー発生時は `ERROR(type)` へ遷移し、UI 表示とリカバリ操作を要求。
- ログ：共通 logger で JSON Lines 出力（vision.log, dialogue.log, arm.log）。`E_*` 発生時に Slack/webhook 通知できるようオプションを残す。
- 排他制御：WebSocket 接続ごとにセッション ID を払い出し、操作 API 呼び出しには同一 ID を要求。最初に操作した端末がロック保持。

---

## 6. テスト計画

- Vision：照度・マーカー欠損・手サイズ違いでの単体テスト（記録済み画像を回す）。
- Mapping：教材 JSON に対するユニットテスト（Pytest）で bbox 判定・デバウンスを検証。
- Dialogue/TTS：モック Ollama/VOICEVOX を用意し、無関係質問時の応答をスナップショットテスト。
- Arm：シミュレータまたは乾燥走行モードで安全領域チェックとフェイルセーフを検証。
- E2E：UI 操作からアーム動作までの 10 分連続デモを必須とする。

---

## 7. 追加で必要な具体値

上記仕様を実装するために、以下の実値/設定ファイルがまだ必要です。

1. **.env（実値）**：`.env.example` を基に、Ollama/VOICEVOX/Tailscale IP・ホスト名など本番値を記入してください。
2. **so-101 安全領域**：`config/arm_limits.json` の `workspace_xyz`・`safe_pose` の null を実測値に更新。
3. **教材 JSON 詳細**：`materials/material_A.json` / `materials/material_B.json` の bbox（question/line 粒度）を実データで記入。
4. **9 点計測結果**：`config/arm_calibration.json` の (u,v)→(x,y,z) をベンチマーク値で埋める。
5. **CONTROL_PANEL_URL**：Tailscale 内で UI を公開する実ホスト名/IP とアクセス手順を確定（`.env` に反映）。

これらが揃い次第、モジュール実装と統合テストに進行可能となる。
